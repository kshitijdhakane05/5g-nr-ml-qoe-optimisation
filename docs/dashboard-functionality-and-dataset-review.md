# Dashboard redesign, functionality inventory, and dataset decision

Review date: 2026-10-29. This is the regression inventory for the dashboard refresh and the evidence gate for dataset/model changes.

## Framework decision

The application is a single-process Streamlit dashboard (`app.py`) with shared Python modules under `dashboard/`, Plotly figures, session-state forms, and direct calls into the current ML, optimizer, simulation, and persistence APIs. Simulation starts only after an explicit form submission. Persisted simulation sessions are read from JSON/JSONL and CSV files. Streamlit already supports the required forms, controls, navigation, charts, and data tables; a React or alternative-framework migration would require recreating stateful forms and file-backed session handling, plus a new frontend/backend boundary, without a measurable capability gain for this project. Retain Streamlit and improve the shared theme and navigation. No backend or simulation semantics changed for the redesign.

## Baseline data and model contract

- Active raw data: `data/raw/qoe_dataset.csv`, 720 flow rows × 15 columns, 120 `scenario_id` groups. Active processed data: `data/processed/qoe_dataset.csv`, 720 × 22; the extra columns are derived features, not new observations. Existing detailed audit: [`data-and-measurement-audit.md`](data-and-measurement-audit.md).
- The original raw dataset is also preserved at `data/backup/qoe_dataset_original.csv`; it is a byte-for-byte copy. Active paths were not changed.
- Current artifact: `models/qoe_model.joblib`. The current target is `qoe_proxy`, a dimensionless, hand-designed ns-3 score in [0,1], not a subjective user rating. It is zero on no-reception rows; otherwise the simulator derives it from throughput (Mbps), one-way delay (ms), jitter (ms), and fractional packet loss.
- Predictor inputs: `ue_count`, `bandwidth_mhz`, `total_tx_power_dbm`, `scenario_size_m`, `flow_type_id`, `flow_lambda` (packets/s), `packet_size_bytes`, and `offered_throughput_mbps`. `scenario_id` and `flow_id` are excluded. Training/evaluation group by scenario to avoid splitting flows from one simulated scenario across train and test.
- Preprocessing maps the traffic class and derives nominal offered throughput. The audit notes a parity issue: training derives offered throughput using observed `tx_packets`, while inference derives it from configured packet rate and packet size. Resolve this before any future training contract change. `lost_packets` is a distinct FlowMonitor field and is not the packet-loss fraction.
- Re-ran `ml.train` on the active processed CSV with seed 42, a scenario-grouped 80/20 holdout (96 train scenarios / 590 rows; 24 test scenarios / 130 rows), and five-fold `GroupKFold` on training scenarios. Overlap was 0. Random Forest test MAE 0.0162, RMSE 0.0445, R² 0.9812; CV MAE 0.0189, RMSE 0.0525, R² 0.9618. Linear Regression test MAE/RMSE/R² 0.0552/0.0883/0.9261; HistGradientBoosting 0.0184/0.0462/0.9798; Dummy mean 0.3144/0.3265/−0.0097. Reproduction artifacts are stored at `results/experiments/qoe_baseline_20261029/`; the active model was not overwritten. The outage-heavy test distribution and fixed 35 dBm / two-bandwidth design limit generalization claims.

### Decision and model status

Neither candidate is a verified, compatible larger replacement dataset for the current QoE model. RANalyzer is larger but only overlaps on some QoS outcomes, lacks latency and QoE labels, has missingness and provenance/semantics questions, and represents a different network. TU Wien is strongly documented but small and has no QoE label. Deriving a new “QoE” from either dataset would require unsupported assumptions and would not validate subjective user experience.

Therefore no candidate preprocessing, dataset path, active model artifact, model target, or controller inference contract was changed, and no model was promoted. The current trained artifact and results remain the production baseline. A prior isolated TU Wien experiment is already present at `results/experiments/tuwien_kpi_baseline_20261026/`; it trained separate ridge regressions using configured rate and known-site category, with six-fold grouped OOF validation by the 42 location/rate conditions (seed 20261026). It is not an alternative QoE model. Across 210 throughput, 207 valid latency, 210 jitter, and 210 packet-loss trials, ridge MAE was respectively 2.314 Mbps, 2.932 ms, 0.144 ms, and 0.0736 percentage points. Against a fold-local global-mean baseline, ridge reduced MAE for all four targets; however, the subsequent rate-only comparison found rate-only MAE lower than ridge for all four targets (0.390 Mbps, 1.688 ms, 0.0277 ms, and 0.0657 percentage points). This indicates the location/rate ridge candidate is not supported as the preferred predictor under that estimand. It remains offline and does not transfer to ns-3 by evidence available here.

The existing production QoE baseline remains the comparison reference: the repository reports grouped scenario holdout MAE 0.0162, RMSE 0.0445, R² 0.9812 for Random Forest. Those scores and the TU Wien KPI scores are not comparable because the datasets, target definitions, units, and split groups differ. A new RANalyzer study would need approved data-license scope, field semantics, a leakage-resistant release/time split, target-specific baselines, and fresh-ns-3 transfer evaluation; it would still not replace the current QoE model.

## Redesign scope

Retained Streamlit and the existing page/control architecture. The workspace now has a light, high-contrast teal/navy visual identity, a clear active-route indicator, consistent card and form surfaces, and readable chart styling. The overview was reorganized around one latest validated run: QoE proxy and run configuration first, then measured throughput, one-way latency, jitter and packet loss, followed by the run trend and concise session index. The experiments page now starts with a compact session index and collapsed status filters; selecting a session exposes validated-run/attempt/score/controller summaries and retains configuration, run history, timeline and file downloads. Primary routes also support direct `?view=run|overview|experiments|analytics|tools` links. All displayed values come from persisted ns-3 session records or the existing measured/prediction calculations; missing values are labeled, and invalid runs remain excluded or shown as gaps according to the existing logic. The run controls, topology search, controller settings, target/stability checks, model tools, explorer, optimizer, verification and persistence flows remain accessible. No metrics, QoE thresholds, controller choices, simulation behavior, or data semantics were altered.

The running application was captured and visually inspected in Edge at 1440×1050 for Run simulation, Overview, Experiments and Analytics. The session index was adjusted after inspection to fit the laptop-width content area. Remaining routes were exercised through the Streamlit app smoke test; no simulation was started during visual review.
